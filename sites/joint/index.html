Two tools, one job each

Prevent with Cephalo. Detect and respond with SideEye.

Cephalo is the seatbelt. SideEye is meant to be the one watching the road. Neither needs the other.

PreventReleased

Cephalo

The seatbelt for AI coding agents.

✕ BLOCK claude/Bash [no-drop] psql -c "DROP TABLE users;"

  • Checks every shell command, file access and MCP tool call against rules you own, before it runs. Hooks into Claude Code and Hermes Agent.
  • A Node.js command-line tool for Windows, macOS and Linux. Windows is the platform it has been run on for real; macOS and Linux are covered by unit tests only.
  • Runs on your machine. No telemetry in the code. MIT licence. Version 0.1.1 is released and stays free; 0.2.0 launches Nov 10, 2026.

Limit: it matches text patterns. A command assembled at run time, or hidden inside a script file, can slip past. It is a seatbelt, not a sandbox.

Why two layers

Rules stop what you predicted. Behaviour catches what you didn't.

Cephalo checks each tool call against rules you wrote and blocks the ones that match, before they run. That works for the things you thought of. It does not understand what a script does once it runs, and a rule can only match what you imagined.

SideEye is meant to cover the rest: learn what each agent normally does, and notice when one stops acting like itself, even with commands no rule blocks. That layer is Planned. It is not built.

  1. Agentasks to run a tool call
  2. Cephalo · beforeALLOW or BLOCK against your rules, before the call runs. Released
  3. The toolruns, if it was allowed
  4. SideEye · afterCompare what the agent did with what is normal for it. Planned
  5. SideEye · respondFLAG, then contain the agent. Planned

Neither requires the other. Today they share one thing: SideEye can read Cephalo's log. Neither is a sandbox, and anything running as you outside the agent's hooks can change both.

        FAQ

        Short answers.

        Do I need both?

        No. Cephalo is released and works alone. SideEye is not installable yet. If you know what you want blocked, Cephalo is enough to start. Use the chooser if you are unsure.

        Does SideEye require Cephalo, or the other way round?

        No, neither requires the other. Today SideEye reads Cephalo's log, and the approval hand-off is in development. If SideEye is closed or in Audit mode, Cephalo behaves exactly as it did before.

        Do they slow my agent down?

        Cephalo runs as a hook before each call. Its optional local-model judge takes about 3 seconds on a CPU, per its site, and is off by default. SideEye is not in the action path today, so it adds nothing to a call; in Enforce mode a held action waits for you, up to 40 seconds. SideEye's target of under 5 ms per action could not be measured, because it is not in that path.

        Does anything leave my machine?

        Not from SideEye. Cephalo makes network calls only to MCP servers you configured, to an Ollama address you set if you turn a model role on, and through gh for its cost report. Neither has telemetry. See the data table.

        What happens if one crashes?

        If Cephalo's hook crashes or gets invalid input, the call is allowed and the error is logged, so a broken guard never freezes your agent. That means a crash lets a call through. If SideEye crashes or is closed, Cephalo behaves as before. If SideEye is open in Enforce mode and does not answer a hold, the action is blocked after 40 seconds.

        Can an agent turn them off?

        Cephalo has rules that stop agents from writing the Claude Code or Hermes config, its own rules file, audit log and vault files. They are rules, not a sandbox: you, or anything running outside the hooks, can still edit those files. SideEye has no such protection yet; tamper protection is Planned.

        Does a Cephalo block hold with --dangerously-skip-permissions?

        For Claude Code, per its documentation, yes: a hook that returns a deny blocks the call even then. Cephalo's author has not confirmed it for Hermes.

Cephalo

The seatbelt for AI coding agents.

Checks every shell command, file access and MCP tool call from your agent against rules you own, and refuses the dangerous ones before they run.

✕ BLOCK claude/Bash [no-drop] psql -c "DROP TABLE users;"

  • Hooks into Claude Code and Hermes Agent. Codex and Cursor adapters are tested against the vendors' documented formats, not run inside the real apps.
  • A Node.js command-line tool for Windows, macOS and Linux. Rules are plain YAML you own.
  • Runs on your machine. No telemetry in the code; the audit log stays in ~/.cephalo.
  • Open source, MIT licence. Version 0.1.1 is released and stays free; 0.2.0 launches Nov 10, 2026.

Limit: it matches text patterns. A command assembled at run time, or hidden inside a script file, can slip past.

SideEye

Every agent gets the side-eye.

Agent detection and response for AI agents. The goal: learn what is normal for each agent on your computer, flag what is not, and contain it.

  • Built Desktop console (Windows build tested). Every number in it is sample data.
  • Built A read-only, live view of Cephalo's audit log on the same machine.
  • In development An approval pop-up for actions Cephalo holds (Claude Code only). It needs a Cephalo change that has not shipped.
  • Planned Per-agent baselines, anomaly flags and containment.

Limit: today it detects nothing on its own. Detection is not prevention, and baselines need a warm-up period before they mean anything.

Why two layers

Rules stop what you predicted. Behaviour catches what you didn't.

Cephalo checks each tool call against rules you wrote and blocks the ones that match, before they run. That works for the things you thought of. It does not understand what a script does once it runs, and a rule can only match what you imagined.

SideEye is meant to cover the rest: learn what each agent normally does, and notice when one stops acting like itself, even with commands no rule blocks. That layer is Planned. It is not built.

  1. Agentasks to run a tool call
  2. Cephalo · beforeALLOW or BLOCK against your rules, before the call runs. Released
  3. The toolruns, if it was allowed
  4. SideEye · afterCompare what the agent did with what is normal for it. Planned
  5. SideEye · respondFLAG, then contain the agent. Planned

Neither requires the other. Today they share one thing: SideEye can read Cephalo's log. Neither is a sandbox, and anything running as you outside the agent's hooks can change both.

Install

Install Cephalo. Six steps, about five minutes.

Cephalo is installed from npm. Tick steps off as you go; your progress stays in this browser. These are the same steps as on the Cephalo site, which has the details.

  1. Node.js 20 or newer. You also need Claude Code, Hermes, or both.

    node --version

  2. One command, the same on every system.

    npm install -g @nomajorconcerns/cephalo

    Then cephalo --help should show the banner and command list.

  3. It prints a plan first, asks before changing anything, creates ~/.cephalo/rules.yml from the defaults, and adds its hook to Claude Code and (if found) Hermes. Every file it edits is backed up to <file>.cephalo-backup-<timestamp>.

    cephalo init

  4. Claude Code reads hooks when it starts, so a running session will not pick up the new hook.

  5. Hermes skips a hook command until you approve it once. Start an interactive hermes, accept the prompt, then check the list. It should say allowed, not not allowed.

    hermes hooks list
hermes hooks doctor

  6. doctor checks the rules file, runs a self-test and confirms the hooks. Then prove a block, and watch decisions arrive live.

    cephalo doctor
cephalo test "DROP TABLE users"
cephalo watch

0 of 6 done · Progress is saved in this browser only.

Undo it any time

cephalo uninstall claude
cephalo uninstall hermes
npm uninstall -g @nomajorconcerns/cephalo

The first two remove only Cephalo's own entries, after taking a backup. The last removes the command. Your rules file stays yours: ~/.cephalo/rules.yml.
